# 2026-W46 — project defined, repository published, first code

Covers 14-15 November 2026.

## What was built
- The project was defined: a free, open-source, offline, cross-platform security self-assessment tool.
- Name chosen: Scudo Digitale ("Digital Shield").
- License chosen: AGPL-3.0 with section 7 attribution terms.
- Accelerated roadmap drafted: about 3 weeks to v1.0 (see [`docs/03-roadmap.md`](../03-roadmap.md)).
- Repository published with the documentation and ADRs 001-004.
- **v0.0 skeleton** (15 November, branch `feature/v0.0-skeleton`):
  - .NET 10 solution with every module of the architecture as a project, each with its test project;
  - `ScudoDigitale.Core` contracts: `ICheck`, `Finding`, `CheckResult`, `Target`, `Profile`, `ScopeDeclaration`, `IScopeGuard`;
  - `CheckEngine`: runs checks with a concurrency limit and a per-check timeout, never lets one failing check stop the others, and runs active checks only after the scope guard says yes;
  - `FindingPrioritizer`: KEV, CVSS, EPSS and confidence turned into one repeatable order;
  - `Attribution`: the mandatory credit line, in one place, used by the CLI banner;
  - `scudo` command line: banner, attribution and warning, in English or Italian depending on the system language;
  - `build/check-headers.ps1`: fails if a `.cs` file lacks the license header;
  - GitHub Actions workflow: build, tests and coverage gate on Windows, Linux and macOS, plus the header check.

## What broke and how it was fixed
- **xUnit v3 no longer runs on VSTest with the .NET 10 SDK.** `dotnet test` stopped with "Testing with VSTest target is no longer supported". Fixed by opting into Microsoft.Testing.Platform in `global.json` and moving coverage from `coverlet.msbuild` to `coverlet.MTP`.
- **The coverage gate failed on a project with 100% coverage.** Two causes. The CLI assembly is called `scudo`, not after its project, so the coverage filter measured nothing. And coverlet counts 0 of 0 branches as 0%, so a project with no branches can never pass a branch threshold. Fixed by letting each test project name its assembly under test, and by gating the CLI on lines only until it gets its first branch.
- **Empty modules fail `dotnet test`**: zero tests is an error (exit code 8) on the new platform. Accepted only for test projects explicitly marked `ModuleNotStarted`, to be removed with the first test.
- **coverlet.MTP silently adds `CompilerGeneratedAttribute` to the exclusions.** In other tools that attribute hides the body of every `async` method. Checked in the report: the async state machines of the engine are still measured.
- **My own counter-check script lied.** To prove the tests catch regressions, a script broke the code on purpose, ran the tests and restored the file. Restoring with `mv` kept the old modification time, so MSBuild considered the project up to date and the next run used the previous, still broken, binary. Fixed with `touch` after each restore and a clean rebuild; all counter-checks were run again.
