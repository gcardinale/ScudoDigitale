# Build journal

Every working week gets one entry, `YYYY-Www.md` (ISO week, e.g. `2026-W46.md`), written at the end of the week.

Each entry covers:
- **What was built**
- **What broke and how it was fixed**
- **Decisions taken** (with links to the ADRs in [`docs/decisions/`](../decisions/))
- **Numbers**: tests, coverage, checks implemented
- **Screenshots/recordings worth showing**
- **Next week's goal**

The journal is honest and factual, with no hype: it is the raw material for public posts about the project. If something did not work, it says so.
